# 工作台怎么运转

[English](../principles.md)

在 `shop/desk` 这样的工作台里，负责人拿主意，协调员规划工作，工作智能体修改文件。`hansa help card` 打印协调员的常设说明；`hansa help principles` 打印本文。

## 1. 钱、密钥和发布由负责人掌管

负责人在网页上定义服务商和模型、设置密钥和 token 价格，并决定哪些发布目标可以免询问发布。这些影响整个工作台的选择，智能体不能修改。协调员可以为工作线选择已配置的服务商，也可以为某件任务另选订阅服务商的模型。这是为了防止智能体自行安排新的开支，或自行取得发布权限。

执行依据：hansa 限制访问权限；协调员的常设说明规定，这些决定由负责人做。

## 2. 协调员规划和判断，代码交给工作智能体

工作智能体在任务分支上修改代码。hansa 运行工作线已配置的检查，协调员在合并前审查每处改动。如果有人直接在工作线的仓库里提交，这些提交会列在把它们发布出去的那次发布记录中。这是为了防止未经审查的改动悄悄进入发布。

执行依据：协调员的常设说明要求这样做；hansa 提供禁止直接编辑的规则，并记录直接提交。

## 3. 一个工作智能体在沙箱里做一件任务

每件任务都在所属工作线的工作副本里使用自己的分支；工作线会重复使用这份工作副本，一次做一件任务。内置工作智能体运行的命令不能提交或推送，不能读取工作台的密钥或内部状态，也不能连接工作线网络名单以外的主机。写入范围限于工作副本、本次运行的临时文件夹，以及工作线的可写清单。另行获准的网页工具和可选适配器有各自的[限制](concepts.md#限制)，详见[工作智能体与沙箱（英文）](../sandbox.md)。这些限制能减少工作智能体犯错或读到恶意内容后造成的损害。

执行依据：hansa 为内置工作智能体落实沙箱和 git 限制。

## 4. hansa 自己检查结果

工作智能体成功完成运行并留下改动后，hansa 会提交这些改动；如果工作线配置了检查命令，就在该分支上运行检查。hansa 记录自己检查得到的结果，因此工作智能体光在报告里声称成功，并不能让检查通过。

执行依据：工作线配置了检查命令时，由 hansa 落实。

## 5. 另派一个工作智能体核验代码，最好换个模型

另一个工作智能体会实际试用改动，并尝试少见的情况。如果测试有改动，核验说明要求它先撤销代码改动，看看哪些测试会失败，再恢复代码并给出结论。协调员通过核验所用的工作线，或为它配置的核验工作线，选择核验模型。实际使用哪个模型取决于那条工作线上就绪的服务商；hansa 不保证它与编写改动的模型不同。核验判为“未通过”（does not hold）后，hansa 会阻止合并，除非协调员明确决定仍要合并。这是为了减少编写和核验时出现相同盲点的可能。

执行依据：协调员的常设说明要求代码改动必须核验；hansa 会阻止核验未通过的改动合并。

## 6. 一件任务只有一个目标，一次运行能做完

任务要写清楚怎样才算完成，只要求完成目标所需的工作。一次工作智能体运行做不完的工作，要拆成几件任务。如果任务会交给核验来判断，要附上各种情况的表格，并写明每种少见情况是该拒绝，还是该原样接受。这是为了避免任务含糊、范围越做越大，最后无法公正判断。

执行依据：协调员的常设说明要求协调员这样写任务。

## 7. 停止反复返工

如果核验第二次因为同一类原因判任务未通过，协调员就要停止这一轮反复返工：缩小任务、降低要求，或者从基础分支重新开始。这是为了避免返工的花费超过改动本身的价值。

执行依据：协调员的常设说明要求这样做；连续核验未通过后，hansa 会给出提示。

## 8. 分清核验发现的问题

正常使用中遇到的缺陷要立即修复；任务本身提错了要求，就要重写任务。只有在少见的状态组合下出现的小缺口，可以判为“通过，有备注”（holds, with notes）；这些问题会留在 `hansa gaps` 里，可以标记为稍后处理或不修复，并写明理由。丢失工作、泄露密钥、合并到错误分支，或者谎报检查通过，无论什么情况都必须判为未通过。这是为了避免无休止地打磨，也避免发现的问题被遗忘。

执行依据：协调员的常设说明指导审查；hansa 把这些判断标准交给核验者，并保留备注和处理标记。

## 9. 没有负责人同意，就不发布

合并到工作线的基础分支后就停下。发布需要负责人在网页上同意、用提醒里的一次性代码确认，或者使用负责人已勾选为免询问的发布目标。只有发布所用的内容和条件仍与记录一致，批准才继续有效。禁用词扫描按负责人设置的规则检查，发现匹配内容就拒绝发布。这是为了防止智能体未经负责人授权就发布。

执行依据：hansa 落实发布审批和禁用词扫描；协调员的常设说明禁止直接发布。

## 10. 工作都有记录，负责人不必读代码

任务、报告、核验结论、合并、发布和负责人的待办都会保留。token 用量按负责人所设价格折算，费用可以按席位（协调员、助手、工作智能体或核验任务）、工作线、任务和模型查看。订阅用量折算的金额不是账单；协调员的用量记录有缺失时，hansa 会提示。网页显示哪些事在等负责人、改了什么、花了多少钱；协调员替负责人操作 hansa。这是为了避免决定、改动和开支失去记录。

执行依据：hansa 保存并显示记录；协调员的常设说明把操作工作交给协调员。
